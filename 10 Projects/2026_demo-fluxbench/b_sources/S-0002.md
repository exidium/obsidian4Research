## Summary
- Field applications engineer covering about forty accounts; logs twenty-five to forty tool cases a month (about forty percent silent parameter resets, twenty percent licensing, fifteen percent model-versus-bench mismatch, ten percent file compatibility). Reset cases take twenty minutes, license cases two to four hours; most never become tickets, so official counts are about a fifth of the real volume.
- Part changes silently reset hidden defaults (switching frequency, ESR, derating, ambient temperature, compensation); customers say "I didn't touch that" and "your tool lied to me". Maintains a twelve-item, symptom-organised "Before You Trust The Number" PDF (version seven) that customers tape to the bench; checklist-based training halves tool cases per account, a feature tour changes nothing.
- Model updates apply silently on reopen and change old results; proved only by comparing against a never-updated second laptop. Wants model versions stored in the file, a dialog on open with a one-line change summary and a side-by-side diff, and old models kept available for regulated customers who otherwise freeze the tool in per-project VMs.
- Licensing fails on roughly half of site visits (air-gapped labs, guest Wi-Fi blocking the check-in port, defense-adjacent rooms with no devices); project files do not open across versions, so support runs on screenshots, PDFs and paper. Wants a thirty-day offline grace period and designs shared like silicon: a browser link, read-only, with the advanced values and a comment thread.
- One in four eval kits differs from the model defaults; proposes a QR code on the board that loads its exact bill of materials. Competitors (invented) win on a change summary after part swaps and a plain-text file format that opens every version. Would cut the news feed, 3D view, assistant panel and update nag; would measure success by tool-question share falling from a third to fifteen percent and by first-try bench matches. Magic wand: the tool never changes a value without saying so.
